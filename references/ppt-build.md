# 页面制作：把结构提纲变成可讲、可核对的页

## 一、先定义可复用块

| 块 | 用途 | 典型位置 |
|---|---|---|
| `stats` | 大数字、单位、证据 ID 与一句解释 | 场景页、参数页 |
| `steps` | 编号、标题、说明和必要注释 | 流程、架构、边界 |
| `cards` | 做法、理由与代价 | 关键动作、设计取舍 |
| `kv` | 左窄标签、右侧解释 | 参数和约束 |
| `table` | 全档位对照、误差与基线比较 | 验证页 |
| `note` | 核心判断、风险和边界 | 任意页 |
| `quote` | 一句话核心结论 | 标题下或转折页 |
| `chart` | 真实定量数据或明确标注的示意图 | 证据页 |

先保证块的样式与数据接口一致，再拼页面，避免每页重新设计。

## 二、页面信息骨架

```text
问句标题
核心结论句（直接回答标题，含必要前提）
────────────────
证据区：图 / 表 / 流程 / 对照
解释区：视觉引导、原因、限制
────────────────
承接句：本页结论如何引出下一页
页脚：来源位置 | 页码
```

第一张内容页必须给全篇核心判断和前提。标题与核心结论句承担不同功能，不互相重复。

## 三、Visual–Claim 绑定

每张关键图在结构提纲和逐页详解中记录三个字段：

| 字段 | 必须回答的问题 |
|---|---|
| `visual_anchor` | 使用哪个来源的哪张图/表/子图？横纵坐标、比较维度和单位是什么？ |
| `callout` | 观众应看哪个突变点、区间、极值、误差棒或对照组？ |
| `claim` | 这张图具体支持哪一句结论，证据强度到哪里？ |

视觉引导使用清晰的框、箭头或局部放大，避免无意义装饰。高亮不能遮盖误差、坐标轴或不利数据。

## 四、图表使用边界

### 定量图

- 只使用证据台账中可追溯的数值；从图上估读必须标注“图上估读”。
- 保留轴名、单位、图例、样本数和必要误差信息。
- 没有具体数值时，不绘制貌似精确的曲线。

### 概念与机制图

- 可以绘制架构、机制路径、实验矩阵和层级关系。
- 明确标注“示意图”，避免把概念关系伪装成定量结果。
- 示意图中的因果箭头必须有原文依据或标为本次推断。

## 五、排版与可读性

- 16:9 页面可从 1280×720 设计稿开始，但以实际 PPT 工具尺寸为准。
- 标题预留两行；核心结论句不与图表争空间。
- 投影场景正文尽量不低于 18 pt；原有工具若使用不同单位，按实际渲染效果校准。
- 层级依靠字号、字重和留白，不依赖过多颜色。
- 表格行过多时优先拆页或提炼，不靠极小字号硬塞。
- 每页保留来源位置或证据 ID，页脚不抢正文注意力。

## 六、逐页闭环

每页执行：读取确认后的提纲 → 制作 → 渲染检查 → 核对证据 → 更新逐页详解 → 进入下一页。

重点检查：

1. 页面是否回答了标题，核心结论是否被证据支持。
2. 图表数值是否与证据台账一致，视觉引导是否指向正确区域。
3. 是否溢出、遮挡、压到页脚或因字体替换跑版。
4. 承接句是否来自本页结论，最后一页是否真正收口。
5. 页码、逐页详解和模拟追问是否同步更新。

全部完成后实际打开或渲染整份 PPT。源代码校验不能替代视觉检查。
