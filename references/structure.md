# 结构：让页与页接上

## 承接句的三种写法

放在页面最底部，一句，不超过 40 字。它的作用是**把这一页的结论变成下一页的问题**。

| 类型 | 写法 | 例 |
|---|---|---|
| **暴露新问题** | 答完了，但答案带出一个新的未知 | "设计定了，可只要一个环节做错，这一格就废了" |
| **指出上一页的不足** | 上一页只说了"是什么"，没说"为什么" | "曲线只说变了，没说为什么变" |
| **给出必要性** | 上一页的结论逼出下一页的动作 | "既然只在这段出问题，那能不能少做几套试验" |

**反例（常见的假承接）**：
- "下面我们来看实验部分" —— 这是导航，不是承接，没有语义
- "接下来介绍数据处理" —— 同上
- "实验结果如下" —— 没有把上一页的结论变成问题

## 标题改写对照

| 名词标题（错） | 问句标题（对） | 为什么更好 |
|---|---|---|
| 研究背景 | 一片叶片在热蒸汽里被反复推，它能撑多少次？ | 有主语、有场景、有问号，下一页必须回答它 |
| 研究现状 | 别人做到哪一步，缺的是哪一块？ | 直接指向缺口，而不是罗列文献 |
| 实验方法 | 为什么非得做 4×4 矩阵？ | 把"方法"变成"方法论的必要性" |
| 实验步骤 | 哪些动作做错，这一格数据就废了？ | 从流水账变成决策 |
| 数据链 | 哪一步产出哪些数据，这些数据干什么用？ | 数据和用途绑在一起 |
| 结果分析 | 材料是怎么回应这些折腾的？ | 有对象、有动作 |
| 机理讨论 | 显微镜下到底发生了什么？ | 把"讨论"落到可看的东西上 |
| 结论 | 寿命的坎在哪，为什么在那儿？ | 结论也要有因果，不是清单 |

## 压缩关系表（讲述提纲必备）

讲解稿节数多于讲述拍数时，必须给出这张表，明确"什么不讲"。不讲不等于不重要，而是留作答问储备。

| 讲解稿的节 | 进不进讲述 | 处理方式 |
|---|---|---|
| 一 结论先行 | 进，压缩 | 变成最后一拍的开头一句，或倒装到开场 |
| 五 实验流程 | **不进** | 整节留作答问储备。被问"具体怎么做"时翻这里 |
| 十一 自测五问 | **不进** | 这是讲者自己的准备清单 |

好处：用户知道哪里可以略过，不会因为"内容太多讲不完"而砍错地方。

## 多篇材料：依赖链，不是并列

五篇做成五个同构模板，一定会被评价"没有关联"。正确做法是先判断它们之间的**依赖关系**，再按依赖排序。

```
① 定义"什么叫坏"（综述：术语与判据）
   ↓ 没有统一定义，②的数据不可比
② 怎么测（实验范式：矩阵、锁死、终止判据）
   ↓ 没有②的数据，④的参数一个都标不出来
③ 工艺怎么影响结果（材料/工艺变量）
   ↓
④ 怎么算（本构/损伤模型：实验→标定→仿真→验证）
   ↓ 宏观模型说不清起裂位置
⑤ 微观机制（晶体塑性/多尺度）
```

讲述时用一句话点明依赖："缺了②，④标不出参数"——这比分别介绍五篇更有说服力。

## 信息密度的控制

- 每页信息量可以大，但要**有一个统领句**（页标题），其余信息都是它的支撑
- 表格优先于段落：三列表（步骤 / 数据 / 用途）比一段话清楚
- 数字要标出处：`依据：步骤 06`
- 一页里超过 3 个并列要点，就应该拆页或改成表格
